# PL 时序问题记录

本文记录 `Time_Calibration_wrapper` 在实现过程中遇到的两轮主要时序问题、定位依据、已经实施的处理，以及下一步推荐方案。

> 工具版本：Vivado 2022.2  
> 器件：XC7Z020-CLG400-2  
> PL 输入时钟：50 MHz  
> ADC 采样时钟：32 MHz  
> 测量及 BRAM 写入逻辑时钟：100 MHz

---

## 一、第一次时序问题：100 MHz 测量计算长路径

### 1. 问题现象

第一次完成实现后，时序结果为：

| 指标 | 数值 |
|---|---:|
| WNS | -5.242 ns |
| TNS | -91.804 ns |

负裕量较大，不能通过重新布线或轻微调整布局可靠解决，必须修改 RTL 数据路径结构。

### 2. 主要原因

主要问题集中在 100 MHz 时域测量计算链路：

1. 峰峰值模块在帧末的单个时钟周期内完成了过多工作，包括：
   - 更新最后一个分段的极值；
   - 计算分段峰峰值；
   - 对多个分段结果求和；
   - 删除最大值和最小值；
   - 加入舍入量；
   - 完成常数除法；
   - 产生最终输出。

2. 有效值前级的均方值模块存在：
   - 绝对值或补码转换；
   - 16 位乘法；
   - 宽位累加；
   - 帧末舍入及输出；
   
   这些运算原本组合在较长的数据路径中，乘法器到累加器的路径难以在 10 ns 周期内稳定收敛。

3. PS FCLK、PL Clock Wizard 输出时钟和自定义 CDC 之间的关系没有被完整表达，部分真正的异步跨时钟路径被当作同步路径分析。

### 3. 已实施的修改

#### 3.1 峰峰值计算改为帧末多周期处理

`peak_to_peak_detector.sv` 已改为状态机结构：

1. `STATE_COLLECT`：实时接收一帧采样并计算各分段极值；
2. `STATE_SCAN`：逐周期扫描分段峰峰值；
3. `STATE_TRIM_INIT/STATE_TRIM`：逐周期删除需要舍弃的最大值和最小值；
4. `STATE_ROUND`：单独完成舍入；
5. `STATE_DIV_INIT/STATE_DIVIDE`：采用串行除法计算保留分段的平均峰峰值。

该结构仍可在采集阶段每个时钟接收一个样点，但不会再要求帧末一个时钟周期完成全部统计运算。

#### 3.2 均方值计算增加流水级

`mean_square_calculator.sv` 已进行以下处理：

- 有符号平方结果先进入寄存器；
- 使用 `use_dsp` 引导 Vivado 将乘法及结果寄存器映射到 DSP48；
- 平方累加在后一级完成；
- 帧末平方和先锁存；
- 舍入和结果输出再使用独立一级完成。

这样从输入样点到平方累加器之间不再存在“码值处理 + 乘法 + 宽位加法”的单周期长路径。

#### 3.3 CDC 与时钟约束整理

XDC 中已完成：

- 避免重复创建 50 MHz 主时钟；
- 将 PS FCLK 与 PL Clock Wizard 时钟组声明为异步；
- 只对自定义同步器的第一级输入设置 false path；
- 同步器第一级到第二级仍保留正常时序检查；
- 为顶层状态信号同步寄存器增加 `ASYNC_REG` 属性；
- FIFO Generator 自带的 CDC 约束继续由 IP 自己管理。

### 4. 修改效果

完成上述修改后，内部逻辑已经收敛。最新实现报告中：

| 时钟域 | WNS |
|---|---:|
| PL 32 MHz 内部逻辑 | +22.222 ns |
| PL 100 MHz 测量逻辑 | +1.469 ns |
| PS FCLK 100 MHz 逻辑 | +2.662 ns |

因此，第一次出现的峰峰值、均方值和内部跨时钟长路径已经不是当前 WNS 的来源。

## 二、第二次时序问题：ADC 源同步输入建立时间不足

### 1. 问题现象

内部计算路径优化后，最新 routed timing 结果为：

| 指标 | 数值 |
|---|---:|
| WNS | -0.363 ns |
| TNS | -2.856 ns |
| Setup 失败端点 | 10 |
| WHS | +0.036 ns |
| THS | 0 ns |

设计已完成全部布线，没有 unrouted net 或 routing error。

### 2. 违例位置

10 条 setup 违例正好对应 ADC-A 的 10 位数据输入：

```text
adc_data_a_0[9:0]
    -> IBUF
    -> u_adc_capture/raw_data_a_reg[9:0]
```

最差路径为：

```text
adc_data_a_0[4]
    -> raw_data_a_reg[4]/D
```

该路径的主要参数为：

| 项目 | 数值 |
|---|---:|
| ADC 时钟周期 | 31.250 ns |
| XDC 最大输入延迟 | 26.000 ns |
| FPGA 输入数据路径 | 1.501 ns |
| 数据路径逻辑级数 | 1（仅 IBUF） |
| 最差 setup slack | -0.363 ns |

输入寄存器已经通过 `IOB = "TRUE"` 放入 ILOGIC，数据路径没有普通逻辑和可优化布线，因此：

- 给计算模块继续增加流水级没有作用；
- `phys_opt_design` 很难从该路径取得有效收益；
- 单纯重复运行 Implementation 不能从根本上解决问题。

### 3. 当前 ADC 时序模型

ADC 时钟由 FPGA 通过 ODDR 转发到外部 ADC，ADC 数据再返回 FPGA：

```text
32 MHz 时钟
    -> ODDR
    -> FPGA OBUF
    -> ADC CLK
    -> ADC 转换及输出延迟
    -> FPGA ADC 数据管脚
    -> IBUF
    -> IOB 输入寄存器
```

XDC 当前采用：

```tcl
set_input_delay -clock adc_clk_a_fwd -max 26.000 \
    [get_ports {adc_data_a_0[*]}]
set_input_delay -clock adc_clk_a_fwd -min 0.000 \
    [get_ports {adc_data_a_0[*]}]
```

其中：

- 3PA1030 数据有效延迟按 25 ns 计算；
- 额外增加 1 ns，作为 PCB 时钟/数据偏差余量；
- 因资料中没有可靠的最小出数延迟，`-min` 暂时保守设置为 0 ns。

当前 ADC 转发时钟输出管脚使用 Vivado 默认属性：

```text
SLEW  = SLOW
DRIVE = 12
```

慢边沿 OBUF 的最大延迟使 ADC 采样时钟较晚到达外部器件，进而使返回数据相对 FPGA 内部下一采样沿到达过晚。

### 4. 首选解决方案

将两路 ADC 转发时钟输出设置为快速边沿，驱动能力保持 12 mA：

```tcl
set_property SLEW FAST [get_ports {adc_clk_a_0 adc_clk_b_0}]
set_property DRIVE 12  [get_ports {adc_clk_a_0 adc_clk_b_0}]
```

已在当前 routed checkpoint 上进行不修改布局布线的 what-if 时序验证：

| ADC 时钟管脚设置 | ADC Setup WNS | ADC Hold WHS |
|---|---:|---:|
| SLOW / DRIVE 12 | -0.363 ns | +1.343 ns |
| FAST / DRIVE 12 | +0.168 ns | +1.266 ns |

因此，`SLEW FAST + DRIVE 12` 可以在保留 `26 ns` 最大输入延迟约束的情况下使当前 setup 时序转正，而且不会引入 ADC hold 违例。

提高到 `DRIVE 16` 没有得到进一步的时序收益，因此没有必要增加输出驱动强度。

### 5. 更高裕量的可选方案

如果希望 ADC setup 裕量高于 `+0.168 ns`，可以在 Clock Wizard 中增加一路专用于 ADC 管脚的相位提前 32 MHz 时钟：

| 时钟 | 频率 | 相位 | 用途 |
|---|---:|---:|---|
| `clk_32m` | 32 MHz | 0° | ADC 输入寄存器、FIFO 写时钟 |
| `clk_32m_adc` | 32 MHz | 约 -3° 至 -6° | 仅用于 ODDR 转发 ADC 时钟 |
| `clk_100m` | 100 MHz | 0° | 测量、BRAM 写入及控制逻辑 |

在 32 MHz 下：

- `-3°` 约等于提前 0.260 ns；
- `-6°` 约等于提前 0.521 ns。

转发时钟提前后，ADC 数据会更早返回 FPGA，从而增加 setup 裕量。该方案需要重新生成 Clock Wizard、修改 `clock_tree` 连接，并重新检查 setup 和 hold，不能只根据估算直接确定最终相位。

### 6. 不推荐的处理

不应采用以下方法掩盖问题：

1. 不要将 ADC 数据输入路径设置为 false path；
2. 不要把 ADC 时钟与输入寄存器时钟声明为异步；
3. 不要仅为了使报告变绿而随意减小 `set_input_delay -max 26 ns`；
4. 不要删除 ADC 的输入延迟约束；
5. 不要依赖重复运行 Implementation 碰运气。

只有在确认实际 PCB 时钟/数据走线偏差小于当前预留的 1 ns 后，才能根据真实板级参数调整最大输入延迟。

### 7. 关于 ADC-B

当前顶层参数为：

```verilog
ADC_CHANNEL = 0
```

因此只有 ADC-A 数据进入后续 FIFO 和测量链路，ADC-B 输入寄存器在综合时被优化，最新报告中只出现 ADC-A 的 10 条被检查路径。

这不表示 ADC-B 天然满足时序。给两路 ADC 转发时钟同时设置 `SLEW FAST`，可以保证以后切换到 `ADC_CHANNEL = 1` 时使用相同的电气属性。正式启用双通道处理后，应确认两路输入寄存器都保留在网表中，并分别检查 ADC-A、ADC-B 的输入时序。

1. 在 `src/constrs/mizar_z7_adc_uart.xdc` 中加入：


3. 重新运行 Implementation；
4. 检查：
   - Design Timing Summary；
   - ADC setup/hold；
   - `clk_out2_clk_wiz_0` 的 100 MHz 内部路径；
   - methodology report；
5. 如果 WNS 虽转正但 ADC setup 裕量仍低于目标，再评估独立相位提前的 `clk_32m_adc`。
