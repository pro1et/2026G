# 16 抽 1 下采样模块设计报告

## 一、设计目标

本模块位于 FIR 滤波器与 Hann 窗之间，负责把 FIR 输出的 32 MSPS、每帧
65536 点有符号采样流转换为 2 MSPS、每帧 4096 点采样流，供后续 4096 点
Hann 加窗和 FFT 使用。

固定参数关系如下：

```text
FIR 输出采样率       = 32 MHz
抽取倍率             = 16
下采样输出采样率     = 2 MHz
FIR 输入帧长度       = 65536 点
下采样输出帧长度     = 4096 点
FFT 点数             = 4096 点
FFT 频率分辨率       = 2 MHz / 4096 = 488.28125 Hz
最低基频             = 10 kHz
最高有效信号频率     = 500 kHz
```

下采样模块只执行固定 16 抽 1，不在模块内部进行滤波、加窗、位宽缩放、
FFT 运算或功率谱计算。抗混叠滤波由前级 FIR 负责。

建议 RTL 文件名：

```text
downsampler_16.sv
```

模块使用 SystemVerilog 编写，并遵循当前工程的模块开发规范。

---

## 二、上下游关系

推荐链路为：

```text
fir_wrap
    ↓ 32 MSPS，65536 点，S16
downsampler_16
    ↓ 2 MSPS，4096 点，S16
hann_window_4096
    ↓ 加窗后的定点采样
FFT 输入缓冲 FIFO
    ↓ AXI4-Stream ready/valid
4096 点 FFT IP
```

当前 `fir_wrap` 所封装的 FIR Compiler 输出端没有 `TREADY`，因此 FIR 输出流
不能被下游反压。下采样模块必须持续接收每一个 `fir_valid` 样点。模块可以对
自身输出提供标准 ready/valid 握手和一个保持寄存器，但不能把 `decim_ready`
反向传播为 FIR 的 ready。

若 Hann 窗模块能够始终接受输入，可以将：

```text
decim_ready = 1
```

若后续可能被 FFT IP 反压，应在 Hann 窗之后增加同步 FIFO。该 FIFO 用于吸收
FFT 配置、启动或内部流水线造成的短暂停顿。FIFO 满导致的丢数必须作为整帧
错误处理，不能静默覆盖数据。

---

## 三、抽取规则

### 3.1 计数依据

所有帧内计数只在以下条件成立时推进：

```systemverilog
fir_valid == 1'b1
```

不能按 100 MHz 处理时钟的自然周期计数，因为 FIR 输出有效样点之间允许存在
空拍。

输入有效样点从 0 开始编号：

```text
0, 1, 2, ... , 65535
```

模块保留输入编号满足以下条件的样点：

```text
input_index mod 16 = 0
```

因此被保留的输入编号为：

```text
0, 16, 32, ... , 65520
```

输出编号与输入编号的关系为：

```text
output_index = input_index / 16
input_index  = output_index × 16
```

输出编号范围为：

```text
0 ... 4095
```

### 3.2 帧尾关系

最后一个下采样输出来自输入样点 65520，而 FIR 输入帧的最后一个样点是 65535。
因此 `decim_last` 会比 `fir_last` 早 15 个有效输入样点出现。这是正常时序，
不能把 `fir_last` 直接连接到 `decim_last`。

模块在产生最后一个下采样点后，仍必须继续消费剩余 15 个 FIR 有效样点，检查
真正的输入帧尾，然后才能返回等待下一帧的状态。

## 四、接口设计

推荐接口如下：

```systemverilog
module downsampler_16 #(
    parameter int unsigned DATA_WIDTH        = 16,
    parameter int unsigned INPUT_FRAME_SIZE  = 65536,
    parameter int unsigned DECIMATION_FACTOR = 16
) (
    input  wire logic                         clk,
    input  wire logic                         rst,
    input  wire logic                         clear_error,

    // FIR 输入流：不可反压
    input  wire logic signed [DATA_WIDTH-1:0] fir_data,
    input  wire logic                         fir_valid,
    input  wire logic                         fir_first,
    input  wire logic                         fir_last,

    // 下采样输出流：标准 ready/valid
    output      logic signed [DATA_WIDTH-1:0] decim_data,
    output      logic                         decim_valid,
    input  wire logic                         decim_ready,
    output      logic                         decim_first,
    output      logic                         decim_last,

    // 状态与诊断
    output      logic                         busy,
    output      logic                         input_frame_done,
    output      logic                         decim_frame_done,
    output      logic                         frame_valid,
    output      logic                         protocol_error,
    output      logic                         overrun_error
);
```

参数约束为：

```text
DATA_WIDTH        > 0
INPUT_FRAME_SIZE  = 65536
DECIMATION_FACTOR = 16
INPUT_FRAME_SIZE mod DECIMATION_FACTOR = 0
```

虽然接口保留参数形式，第一版只支持当前固定配置。若参数不是 65536 和 16，
应在 elaboration 阶段直接报错，避免产生未经验证的硬件。

---

## 五、输入接口语义

### `fir_data`

FIR 输出的 `DATA_WIDTH` 位有符号二进制补码数据。当前为 S16。下采样模块不
改变数值，不执行舍入、饱和或重新定标。

### `fir_valid`

本周期存在一个有效 FIR 输出样点。只有该信号为高时才允许：

* 推进输入样点计数；
* 推进 0～15 抽取相位；
* 检查 `fir_first` 和 `fir_last`；
* 产生新的下采样输出。

### `fir_first`

只允许与输入有效样点 0 对齐。等待新帧时，模块仅以：

```text
fir_valid && fir_first
```

作为新帧开始条件。

等待状态收到 `fir_valid=1`、`fir_first=0` 的样点时，不应把该样点当成新帧第
0 点，而应忽略该样点并锁存 `protocol_error`，继续寻找合法帧首。

### `fir_last`

只允许与输入有效样点 65535 对齐。提前、延后或缺失的 `fir_last` 都属于帧协议
错误。

---

## 六、输出握手语义

下采样输出采用标准 ready/valid 规则：

```text
一次输出传输成功 = decim_valid && decim_ready
```

当：

```text
decim_valid == 1 && decim_ready == 0
```

时，模块必须保持以下信号不变：

```text
decim_data
decim_first
decim_last
decim_valid
```

直到该样点被成功接收。

模块内部使用一个输出保持寄存器。由于 FIR 输入不能反压，如果上一个下采样点
尚未被接收，而 16 个新的 FIR 有效样点已经到来并产生下一个应保留样点，则无法
保存新的样点。此时必须：

1. 锁存 `overrun_error`；
2. 将当前帧标记为无效；
3. 不得覆盖尚未接收的旧输出；
4. 系统顶层不得使用该帧的 FFT、频谱、基频和能量结果。

在正常配置下，相邻下采样输出之间约有 16 个 FIR 有效样点，即约 50 个 100 MHz
处理时钟周期，Hann 窗或下游 FIFO 有充分时间接受前一个输出。

输出保持寄存器应支持“本周期旧数据被接收，同时装入新数据”的情况：

```text
decim_valid && decim_ready && selected_input
```

尽管在固定 16 抽 1 下通常不会连续产生输出，实现仍应正确处理该组合条件。

---

## 七、帧标志与完成信号

### `decim_first`

只与输出编号 0 对齐，即输入编号 0 被保留时产生。

### `decim_last`

只与输出编号 4095 对齐，即输入编号 65520 被保留时产生。

`decim_first` 和 `decim_last` 只有在 `decim_valid=1` 时有意义，并且在输出被
反压时必须和数据一起保持。

### `decim_frame_done`

最后一个下采样输出完成握手时产生一个时钟周期：

```text
decim_valid && decim_ready && decim_last
```

该信号表示后级已经接收完整的 4096 点 FFT 输入帧，不表示原始 65536 点 FIR
输入帧已经全部消费。

### `input_frame_done`

成功接收并检查输入编号 65535 后产生一个时钟周期。该信号比无反压情况下的
`decim_frame_done` 晚 15 个 FIR 有效样点。

### `frame_valid`

与 `input_frame_done` 同周期有效，表示刚完成的输入帧是否可以用于频域结果：

```text
frame_valid = 本帧没有协议错误且没有输出覆盖错误
```

需要特别注意：FFT 可能已经在处理4096点数据。因此一旦 `frame_valid=0`，顶层
必须禁止 Spectrol 提交该帧结果，必要时复位 FFT 数据通路。

---

## 八、内部计数器

建议使用以下寄存器：

```systemverilog
logic [15:0] input_index;   // 0～65535
logic [3:0]  phase_count;   // 0～15
logic [11:0] output_index;  // 0～4095
logic        frame_error;
```

抽取条件为：

```systemverilog
selected_input = fir_valid && busy && (phase_count == 4'd0);
```

新帧首本身也属于第0个有效样点，因此在接受：

```text
fir_valid && fir_first
```

的同一上升沿，应装入第0个下采样输出，并将其 `decim_first` 置位。

每收到一个有效输入样点：

```text
phase_count = 15 → 下一值为 0
其他值          → 加 1
```

当 `phase_count=0` 时，输出编号推进一次。输出编号4095之后不再产生新的下采样
输出，但输入计数继续推进到65535。

不得使用普通时钟分频信号作为下采样时钟。所有逻辑始终工作在100 MHz处理时钟
域，下采样结果仅通过 `decim_valid` 表示2 MSPS的有效速率。

---

## 九、推荐状态机

建议使用三个状态：

```systemverilog
typedef enum logic [1:0] {
    STATE_WAIT_FIRST,
    STATE_COLLECT,
    STATE_ERROR
} state_t;
```

### `STATE_WAIT_FIRST`

* 等待 `fir_valid && fir_first`；
* 合法帧首到来时初始化计数器并立即处理第0点；
* 无帧首的有效数据被忽略并锁存协议错误；
* 允许在该状态通过 `clear_error` 清除粘滞错误。

### `STATE_COLLECT`

* 对每个 `fir_valid` 样点推进输入计数和抽取相位；
* 每16个有效输入产生一个下采样输出；
* 检查输入帧首、帧尾位置；
* 输入编号65535完成后产生 `input_frame_done`，然后回到等待状态。

普通帧标志不匹配时，建议继续按照固定有效样点计数消费到65535，以免破坏 FIR
链路；同时置位本帧 `frame_error`。如果发生输出保持寄存器覆盖风险，则进入
`STATE_ERROR`，因为该帧已经不可恢复。

### `STATE_ERROR`

* 停止产生新的下采样输出；
* 继续消费或等待上游完成当前帧；
* 保持错误标志；
* 由顶层执行协调复位后恢复。

不建议只通过 `clear_error` 恢复输出覆盖错误，因为 FFT、Hann 窗和输入缓冲中
可能已经保存部分错误帧。此类错误应复位整条频域支路。

---

## 十、错误定义

### `protocol_error`

以下任一情况置位：

1. 等待帧首时收到无 `fir_first` 的有效样点；
2. 输入编号不为0时收到 `fir_first`；
3. 输入编号65535之前收到 `fir_last`；
4. 输入编号65535没有收到 `fir_last`；
5. 固定计数得到的输出数量不是4096；
6. 新帧到来时上一帧尚未完成。

### `overrun_error`

需要产生新的下采样点时，输出保持寄存器仍保存未被接收的数据，则置位该错误。

两个错误均为粘滞状态，正常情况下保持到复位或安全的错误清除流程。错误信号应
接入频域顶层的总错误状态，并作为禁止提交 Spectrol 结果的条件。

---

## 十一、抗混叠和有效频带说明

16 抽 1 后采样率为2 MHz，理论奈奎斯特频率为1 MHz。当前系统规定所有有效
频率不超过500 kHz，因此有效信号带宽位于新奈奎斯特频率以内，并为滤波器过渡
带留出了500 kHz余量。

当前前级129阶 FIR 在500 kHz附近基本保持单位增益，在约750 kHz进入过渡带，
1 MHz及以上约有33 dB抑制。该特性与当前0～500 kHz有效频带方向一致。

但“有效信号不超过500 kHz”不等于500 kHz以上完全没有 ADC 噪声或干扰。后续
仍应通过 MATLAB 黄金模型和实测数据确认33 dB阻带抑制能否满足弱谐波检测要求。
如果不能满足，应修改前级抗混叠 FIR，而不是在本模块中简单改变抽取相位。

---

## 十二、与 Hann 窗模块的连接约定

下采样模块输出给 Hann 窗的样点必须满足：

```text
数据格式：16位有符号二进制补码
帧长度：  4096个成功握手的样点
帧首：    输出编号0
帧尾：    输出编号4095
```

Hann 窗模块的系数地址应根据成功的下采样输出握手推进：

```text
decim_valid && decim_ready
```

不能根据 `decim_valid` 单独推进，否则下采样输出被反压时会造成样点与窗系数错位。

Hann 窗模块应在接受 `decim_first` 时把系数地址置为0，并在接受 `decim_last` 时
检查当前系数地址是否为4095。

---

## 十三、时序和资源预估

本模块数据通路只包含：

* 一个16位输出保持寄存器；
* 一个16位输入计数器；
* 一个4位抽取相位计数器；
* 一个12位输出计数器；
* 少量比较和控制逻辑。

不需要乘法器、除法器、DSP48或BRAM。固定16抽1应通过4位相位计数实现，不应
综合通用除法或取模逻辑。

相邻输出间隔很长，100 MHz时序压力较低。关键控制信号仍应寄存，不应把下游
`ready` 经过较长组合路径直接反馈到 FIR 输入控制。

---

## 十四、仿真验证计划

应为模块编写自检查 testbench，建议文件名：

```text
downsampler_16_tb.sv
```

至少覆盖以下测试：

1. 连续输入65536点，检查输出恰好4096点；
2. 输入数据使用递增编号，检查输出依次为0、16、32直到65520；
3. 检查 `decim_first` 只与输出0对齐；
4. 检查 `decim_last` 只与输出4095对齐；
5. 检查 `decim_last` 对应输入编号65520，而不是65535；
6. 在 `fir_valid` 中插入随机空拍，确认抽取结果不变；
7. 在第一个输出到来时拉低 `decim_ready`，检查数据和帧标志保持；
8. 在中间输出到来时随机反压，并在16个有效输入内恢复；
9. 同周期接收旧输出并装入新输出；
10. 反压超过16个有效输入，检查 `overrun_error`；
11. 等待状态输入无 `fir_first` 的有效数据，检查忽略和报错；
12. `fir_first` 出现在错误输入位置；
13. `fir_last` 提前出现；
14. 输入编号65535缺少 `fir_last`；
15. 输入末尾15点存在随机空拍，检查 `input_frame_done` 时序；
16. 检查 `decim_frame_done` 与最后一个输出成功握手严格对齐；
17. 连续处理两帧，检查计数器、相位和帧标志在帧间正确重置；
18. 第一帧错误后第二帧不得继承旧的相位和输出计数；
19. 帧处理中复位，检查所有 valid、done 和计数器清零；
20. 错误清除流程不会误产生输出或完成脉冲。

Testbench 不能只检查最终输出数量，还应逐点比较：

```text
expected_output[n] = input_frame[16 × n]
```

并断言：

```text
0 <= n <= 4095
```

所有输出握手、帧边界和错误状态都应自动判定通过或失败。

## 十五、端到端验证要求

模块单测通过后，还应使用 MATLAB 或等效参考模型验证：

```text
32 MSPS原始数据
→ 当前FIR系数
→ 每16个有效输出取第0个
→ 4096点Hann窗
→ 4096点FFT
→ 正频率功率谱
```

至少使用以下信号：

1. 10 kHz单频正弦；
2. 10.5 kHz单频正弦；
3. 20 kHz基波及40/60 kHz谐波；
4. 499.5 kHz单频正弦；
5. 500 kHz单频正弦；
6. 多频信号且所有分量不超过500 kHz；
7. 带宽外噪声或干扰，用于评估抽取混叠；
8. 最大允许幅值，用于检查加窗和FFT后级位宽。

RTL 输出的4096个下采样点必须与参考模型逐点一致，之后才能开始验证 Hann 窗、
FFT和功率谱模块。

## 十六、最终实现原则

1. 固定执行16抽1，不在模块内派生2 MHz时钟；
2. 只按 `fir_valid` 统计有效输入样点；
3. 每帧65536点严格产生4096个下采样点；
4. 固定保留输入编号0、16、32至65520；
5. 独立重建下采样帧的 `first/last`，不直接转发 `fir_last`；
6. FIR输入不可反压，输出阻塞必须由保持寄存器和后级FIFO吸收；
7. 任何输出覆盖风险都必须报错，并使整帧频域结果无效；
8. 下采样模块不改变样点数值和定点格式；
9. 顶层必须在 FFT 前准备好 Hann 窗和输入缓冲，再允许新帧进入频域支路；
10. 完成模块级自检查仿真后，再进行整条频域链的定点一致性验证。
