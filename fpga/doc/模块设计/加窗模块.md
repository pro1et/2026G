# 4096 点 Hann 加窗模块设计说明

## 1. 模块概述

`hann_window_4096` 位于 16 抽 1 下采样模块与 4096 点 FFT IP 之间，负责将一帧
4096 个 16 位有符号样点逐点乘以周期型 Hann 窗。模块不改变帧长度和采样率，
输出仍为 4096 点、16 位有符号二进制补码数据。

当前频域处理链路为：

```text
FIR 输出：32 MSPS，65536 点，S16
    ↓
16 抽 1 下采样
    ↓ 2 MSPS，4096 点，S16
hann_window_4096
    ↓ 2 MSPS，4096 点，S16
4096 点 FFT IP
```

相关工程文件：

```text
RTL模块：        fpga/src/hdl/hann_window_4096.sv
ROM IP：         fpga/src/ip/hann_rom_0/hann_rom_0.xci
窗系数：         fpga/src/ip/hann_4096_half_q15.coe
模块Testbench：  fpga/src/sim/hann_window_4096_tb.sv
```

## 2. 采用周期型 Hann 窗的原因

4096 点周期型 Hann 窗定义为：

\[
w[n] = \frac{1}{2}\left(1-\cos\frac{2\pi n}{4096}\right),
\qquad 0\le n\le4095
\]

加窗输出为：

\[
y[n] = x[n]w[n]
\]

周期型窗适合送入同长度的 FFT。它把长度为 4096 的采样序列视为一个周期，窗
系数满足：

```text
w[0] = 0
w[2048] = 1
w[n] = w[4096-n]，n=2049～4095
```

与矩形窗相比，Hann 窗可以显著降低频谱泄漏；与 Hamming 窗相比，Hann 窗端点
趋近于零，更适合当前需要在非整 FFT 频点条件下检测基频和谐波能量的应用。

这里必须使用 MATLAB 的 `hann(4096, 'periodic')`，不能使用 `symmetric`。周期型
Hann 的分母是 4096，而对称型 Hann 的分母是 4095，两者的系数、镜像关系以及
FFT 结果均不相同。

## 3. 数据格式与定点运算

### 3.1 输入和输出

```text
sample_data：  16位有符号二进制补码，S16
window_data：  16位有符号二进制补码，S16
ROM系数：      16位非负Q1.15，范围0～32767
内部乘积：     32位有符号数
```

Q1.15 系数由 MATLAB 浮点窗系数量化得到：

\[
w_{Q15}[n]=\operatorname{round}(32768w[n])
\]

因为 Q1.15 的最大正数是 32767，所以中心点的数学值 1 用 32767 表示。RTL 的输出
计算为：

\[
y[n]=\operatorname{round}\left(
\frac{x[n]w_{Q15}[n]}{32768}
\right)
\]

正乘积加入 16384 后算术右移 15 位；负乘积加入 16383 后算术右移 15 位。这种
符号相关偏置用于实现关于零对称的最近值舍入：

```systemverilog
if (sample_d1[15])
    rounded_product = sample_d1 * coefficient + 16383;
else
    rounded_product = sample_d1 * coefficient + 16384;

window_data = rounded_product >>> 15;
```

所有 Hann 系数均不大于 1，因此合法的 S16 输入不会因加窗而发生幅值溢出，无需
额外的饱和模块。中心点使用 32767/32768 近似 1，极端输入可能比数学理想值相差
1 LSB，这是 Q1.15 表示范围造成的正常结果。

## 4. 半窗 ROM 设计

完整 4096 点系数不全部存入 ROM。模块利用周期型 Hann 的对称性，仅保存索引
0～2047 的 2048 个系数；中心点使用常量，后半窗镜像读取前半窗。

地址映射如下：

| 样点索引 `n` | 系数来源 | ROM 地址 |
|---:|---|---:|
| 0～2047 | ROM 顺序读取 | `n` |
| 2048 | RTL 常量 `32767` | 不使用 ROM 数据 |
| 2049～4095 | ROM 镜像读取 | `4096-n` |

例如，样点 2049 读取 ROM 地址 2047，样点 4095 读取 ROM 地址 1。样点 0 的系数
为 0，因此无需再次读取地址 0 作为最后一点。

这种结构将系数存储量从 4096×16 bit 降至 2048×16 bit。当前器件综合为一个
`RAMB36E1`。

### 4.1 `hann_rom_0` 配置

Block Memory Generator IP 的关键参数如下：

| 配置项 | 当前值 |
|---|---|
| Component Name | `hann_rom_0` |
| Memory Type | Single Port ROM |
| 数据宽度 | 16 bit |
| 深度 | 2048 |
| Enable Port | 使用 `ena` |
| Primitive Output Register | 关闭 |
| Core Output Register | 关闭 |
| 初始化文件 | `hann_4096_half_q15.coe` |
| ROM 读取延迟 | 1 个时钟周期 |

ROM 实例接口为：

```systemverilog
hann_rom_0 u_hann_rom (
    .clka  (clk),
    .ena   (rom_en),
    .addra (rom_addr),
    .douta (rom_dout)
);
```

ROM 的 `ena` 只在输入样点成功握手时有效。这样在输入空拍或输出反压期间，ROM
地址、样点数据和窗系数不会错位。

| `sample_last` | 输入 | 1 | 当前输入为 4096 点帧的第 4095 点 |

## 6. Valid-Ready 握手

输入传输成功条件为：

```text
input_fire = sample_valid && sample_ready
```

只有 `input_fire=1` 时，模块才会：

1. 接收 `sample_data` 和帧标志；
2. 启动 ROM 读取；
3. 推进 0～4095 的窗索引；
4. 检查 `sample_first` 和 `sample_last`。

输出传输成功条件为：

```text
window_valid && window_ready
```

当 `window_valid=1` 且 `window_ready=0` 时，整条流水线冻结，以下信号保持不变：

```text
window_data
window_valid
window_first
window_last
内部样点、系数和帧索引
```

因此 FFT 或输出 FIFO 的短时反压不会造成数据、窗系数和帧标志错位。无反压时，
模块能够每个处理时钟接收并输出一个有效样点。

## 7. 流水线结构

模块采用三个寄存级：

```text
输入握手
    ↓
第一级：锁存S16样点、first/last和中心点标志，同时提交ROM地址
    ↓
第二级：读取Q1.15系数，完成16×16乘法并加入舍入偏置
    ↓
第三级：算术右移15位，寄存S16输出及first/last
```

从某个样点在上升沿成功输入，到对应输出在第二个后续上升沿更新，固定经历上述
流水处理。空拍由各级 valid 传播，不会被当作有效数据；输出反压时所有级同时
暂停。

乘法与舍入偏置被合并到一个 DSP48 乘加运算中。当前 OOC 综合结果为：

```text
DSP48E1：  1
RAMB36E1： 1
目标时钟：100 MHz
WNS：      +3.319 ns
时序结果：满足约束
```

## 8. 帧管理与错误检查

内部 `sample_index` 范围为 0～4095，并且只在输入成功握手后推进。正确帧必须
满足：

```text
sample_index = 0       时 sample_first = 1
sample_index = 1～4094 时 sample_first = 0 且 sample_last = 0
sample_index = 4095    时 sample_last = 1
```

`first` 或 `last` 出现在错误位置、应出现时缺失，都会置位 `protocol_error`。
该错误是粘滞状态，保持到同步复位或 `clear_error=1`。发生错误后模块仍按内部
计数继续处理数据，避免频域链路立即死锁；系统控制器应丢弃该帧的 FFT 和频谱
结果。

第 4095 点成功输入后，索引自动回到 0，准备下一帧。`window_first` 和
`window_last` 与对应加窗数据经过相同流水级，只有在 `window_valid=1` 时才有
意义。

## 9. 与上下游模块连接

### 9.1 连接下采样模块

```systemverilog
.sample_data  (decim_data),
.sample_valid (decim_valid),
.sample_ready (decim_ready),
.sample_first (decim_first),
.sample_last  (decim_last)
```

下采样模块必须每帧提供恰好 4096 点，并保留 FIR 输入索引
0、16、32、……、65520。

### 9.2 连接 FFT

加窗输出可连接 FFT 输入 FIFO，或者在确认 FFT 始终能接收时直接连接 FFT 的
AXI4-Stream 数据输入。推荐映射为：

```text
window_data   → FFT实部输入
常数0         → FFT虚部输入
window_valid  → FFT输入TVALID
FFT输入TREADY → window_ready
window_last   → FFT输入TLAST
```

如果 FFT 配置、启动或内部状态可能造成较长反压，建议在 Hann 模块与 FFT 之间
增加同步 FIFO。虽然本模块能够冻结流水线，但上游 FIR 输出本身不可反压；若
反压持续到下一个 16 抽 1 样点到来，下采样模块会报告输出覆盖风险。

## 11. 使用限制

1. 当前实现固定支持 4096 点周期型 Hann 窗，不支持运行时改变窗长或窗类型。
2. 输入和输出均固定为 16 位有符号数，系数固定为 Q1.15。
3. 工程中必须包含名称和端口一致的 `hann_rom_0` IP。
4. COE 必须包含周期型 Hann 的前 2048 个系数，不能替换为对称型 Hann 系数。
5. 输入帧必须严格使用 `first/last` 标记第 0 和第 4095 个成功握手的样点。
6. 发生 `protocol_error` 或下采样覆盖错误时，不得提交该帧 FFT、基频和谐波
   能量结果。
7. 若未来修改 ROM 输出寄存器或读取延迟，必须同步修改 RTL 流水线对齐关系并
   重新完成 4096 点逐点验证。
