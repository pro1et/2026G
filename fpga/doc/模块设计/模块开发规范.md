FPGA SystemVerilog 模块开发规范

1. 适用范围

本规范适用于本工程中所有 FPGA RTL 模块、接口模块、跨时钟域模块及其仿真文件，包括但不限于：

时钟与复位；

ADC、DAC 接口；

数据预处理与降采样；

BRAM、FIFO 与缓存管理；

FIR 滤波；

PS/PL 通信与控制。

Codex 在新增或修改模块时必须遵守本规范。若现有工程结构与本规范冲突，应先分析影响，不得未经确认大规模重构。

2. 总体开发原则

尽量使用.v而不是.sv

先确定模块职责、上下游关系、输入、输出和参数，再编写内部逻辑。

每个模块只承担一种主要职责，避免模块间依赖彼此的内部实现。

模块接口应稳定、清晰、可独立测试，内部实现可以在不改变接口的情况下替换。

可合理变化的位宽、深度、长度和数量应参数化，禁止散布魔法数字。

不得为了参数化而显著增加无意义的复杂度；真正固定的协议常量可以保留。

每创建一个模块，必须同时设计并完成对应的自检式 testbench。

注释必须使用中文。模块头说明、端口注释、参数注释以及关键逻辑注释均使用中文；行业通用缩写、信号名和工具要求的英文关键字可以保留。

注释重点解释接口约束、设计意图、时序原因和异常行为，不逐行复述代码。

3. 模块设计流程

实现新模块时按以下顺序执行：

分析模块的单一主要职责。

明确上游、下游及其连接关系。

确定模块所属时钟域以及复位来源。

确定参数、输入和输出。

明确数据格式、有效时序和握手协议。

明确启动、结束、错误和复位行为。

给出测试计划，包括正常、边界和异常场景。

接口合理后再编写 RTL。

编写自检式 testbench 并执行仿真。

检查综合、时序、CDC、资源使用及警告。

若需求中的歧义会影响模块接口、数据格式、时钟域或整体架构，必须先向用户确认。不要一次性生成所有模块，应按照系统数据流逐个实现、验证和集成。

4. 模块文件头规范

每个 RTL 文件开头必须提供完整的中文使用说明。目标是让使用者不阅读内部实现，也能正确实例化并连接模块。

模块头至少包含：

模块名称；

主要功能；

使用步骤；

每个接口应连接到哪里；

时钟域与复位要求；

输入数据格式；

输出数据格式；

握手或控制时序；

参数含义与合法范围；

输出何时有效、保持多久；

错误及异常行为；

使用限制；

对输入连续性、吞吐率和延迟的要求。

统一采用以下模板：

// ============================================================================
// 模块名称：
//
// 主要功能：
//
// 使用方法：
//   1.
//   2.
//
// 连接说明：
//   clk      <- 时钟树输出的本模块工作时钟
//   rst      <- 本时钟域的复位同步模块输出
//   data_in  <- 上游模块
//   data_out -> 下游模块
//
// 时钟与复位：
//
// 输入格式：
//
// 输出格式：
//
// 握手时序：
//
// 参数说明：
//
// 错误行为：
//
// 使用限制：
// ============================================================================

5. 端口与参数规范

5.1 端口注释

每个 input、output 和 inout 都必须在端口定义处写中文注释，至少说明：

信号用途；

有效条件；

必要时说明所属时钟域；

数据是否有符号；

定点格式或编码格式；

脉冲信号持续周期；

输出保持规则。

示例：

input  logic                         clk,       // 模块工作时钟
input  logic                         rst,       // 高电平有效的同步复位
input  logic signed [DATA_WIDTH-1:0] data_in,   // 输入采样值，二进制补码 Q1.15
input  logic                         in_valid,  // 输入数据有效，高电平持续一个或多个周期
output logic                         in_ready,  // 模块可接收输入数据
output logic signed [DATA_WIDTH-1:0] data_out,  // 处理后的输出数据
output logic                         out_valid  // 输出数据有效

5.2 命名规则

信号名称简洁、明确，不重复添加所在模块名称。

ADC 模块内部工作时钟命名为 clk，不命名为 adc_clk 或 clk_100m。

只有时钟树的输出端口可以使用 clk_100m、clk_300k 等表示实际频率的名称。

业务模块的端口名称不得绑定当前工作频率，因为同一模块未来可能工作在其他频率下。

推荐采用以下通用名称：

时钟与复位：clk、rst 或全工程统一的 rst_n；

数据：data_in、data_out；

流握手：in_valid、in_ready、out_valid、out_ready；

任务控制：start、busy、done、error；

写接口：wr_en、wr_addr、wr_data；

读接口：rd_en、rd_addr、rd_data、rd_valid。

同一类模块必须保持一致的端口顺序、命名方式和握手语义。

5.3 参数规范

适合参数化的内容包括：

数据位宽；

地址位宽；

缓存深度；

采样点数；

相位累加器位宽；

FIR 系数数量和系数位宽；

并行通道数；

计数器最大值。

每个参数必须有中文注释，说明含义、单位及合法范围。应尽可能在仿真阶段检查参数：

parameter int DATA_WIDTH = 16,  // 输入输出数据位宽，必须大于 0
parameter int DEPTH      = 1024 // 缓存深度，必须为 2 的整数次幂

initial begin
    assert (DATA_WIDTH > 0)
        else $fatal(1, "DATA_WIDTH 必须大于 0");
    assert (DEPTH > 0 && (DEPTH & (DEPTH - 1)) == 0)
        else $fatal(1, "DEPTH 必须为 2 的整数次幂");
end

接口分组

端口列表按以下顺序分组排列：

参数；

时钟与复位；

控制接口；

配置接口；

数据输入接口；

数据输出接口；

状态和错误接口。

7. 时钟与复位规范

7.1 时钟

所有工作时钟统一由时钟树提供。

业务模块不得使用计数器、组合逻辑或普通寄存器输出作为新时钟。

降低处理速率时优先使用 clock enable。

只有确实需要新频率或相位时，才由统一时钟树使用 MMCM、PLL 等专用资源生成。

时钟树只负责时钟和复位相关功能，不承担业务逻辑。

正确示例：

always_ff @(posedge clk) begin
    if (sample_en) begin
        // 仅在采样使能有效时更新数据
    end
end

禁止使用业务逻辑生成的 divided_clk 驱动其他时序逻辑。

7.2 复位

全工程应统一：

复位极性；

同步复位或异步复位方式；

最短有效周期；

异步复位的同步释放方式；

复位期间各输出值；

解除复位后开始工作的周期。

每个时钟域应使用对应的复位同步信号。模块不得假设来自其他时钟域的复位可以直接安全使用。

复位后必须确保：

状态机进入确定状态；

valid、busy、done 和写使能等控制输出处于无效状态；

地址、计数器及缓存状态明确；

不产生虚假的数据传输或完成脉冲。

8. 跨时钟域规范

“所有时钟来自统一时钟树”不代表所有信号都处于同一时钟域。ADC、DAC、处理逻辑、AXI 和 PS/PL 通信可能使用不同的时钟。

跨时钟域必须采用明确的 CDC 结构：

单比特静态状态：双触发器同步；

单周期脉冲：toggle 同步、脉冲展宽或完整握手；

多比特连续数据：异步 FIFO；

块数据：双口 BRAM 配合所有权或完成握手；

配置总线：保持数据稳定并配合请求/确认握手。

禁止：

直接采样异步输入；

对多比特数据总线逐位打两拍；

在没有握手的情况下假设多比特信号会同时稳定；

隐藏跨时钟域关系。

每个跨时钟域端口必须在模块头或端口注释中标明源时钟域和目标时钟域。

9. 数值与定点格式规范

ADC、DDS、IQ、FIR 等数值接口必须说明：

signed 或 unsigned；

二进制补码、偏移二进制或其他编码；

定点 Q 格式；

实际有效范围；

缩放关系；

中间乘积和累加器位宽；

舍入方式；

截位方式；

饱和或回绕策略；

可能发生溢出的条件。

位宽必须有推导依据。例如 FIR 累加器应根据输入位宽、系数位宽和抽头数量估算所需增长位数，不能仅凭经验指定。

算法模块应尽量与 MATLAB 参考模型保持一致，并支持逐级比较：

原始采样；

预处理结果；

I/Q 累加值；

频响计算结果；

FIR 中间乘积；

FIR 最终输出。

若硬件使用定点数而 MATLAB 使用浮点数，测试说明中必须给出量化、舍入及允许误差。

10. SystemVerilog 编码规范

优先使用 logic、always_ff、always_comb 和具有明确类型的 parameter。

时序逻辑使用非阻塞赋值 <=。

组合逻辑使用阻塞赋值 =。

文件中使用 default_nettype none 防止隐式网络；文件结尾恢复工具需要的默认设置。

避免隐式位宽扩展、截断及有符号/无符号转换。

必要时使用显式类型转换，并用中文说明转换原因。

组合逻辑必须为所有输出提供默认赋值，避免产生锁存器。

禁止组合环路和业务逻辑派生时钟。

状态机应使用清晰的枚举类型，并处理非法状态。

计数器边界、数组下标和地址范围必须明确。

不依赖未初始化寄存器的仿真初值实现硬件功能。

关键时序流水线应注释说明延迟周期及数据对齐关系。

11. 模块解耦与职责划分

不要将接口采样、算法处理、缓存、跨时钟域和 PS/PL 握手全部放入同一个模块。

推荐按主要职责拆分，例如：

adc_capture
    -> preprocess
    -> decimator
    -> iq_demod
    -> sweep_buffer
    -> ps_interface

拆分原则：

模块具有清晰、独立的输入输出契约；

模块能够被单独仿真；

替换内部实现时不影响上下游；

CDC、FIFO、BRAM 控制等基础功能可复用；

不为一次简单寄存操作创建没有复用或验证价值的过小模块。

12. Testbench 与验证规范

12.1 基本要求

每个 RTL 模块原则上对应一个独立 testbench。

testbench 必须能够自动判断通过或失败。

优先使用 assert、参考模型和期望值比较。

不得仅依靠人工观察波形判断正确性。

测试必须可重复运行，不依赖人工操作或未固定的随机种子。

测试失败时应打印足以定位问题的信息，包括时间、输入、实际输出和期望输出。

12.2 测试覆盖

根据模块性质至少考虑：

正常工作流程；

最小和最大合法参数；

最大值、最小值、零值及符号边界；

连续输入；

间断输入；

下游背压；

FIFO 或缓存的空、满和溢出；

空闲状态复位；

工作过程中复位；

连续启动；

busy 期间非法启动；

输入不足或输入超量；

跨时钟域两侧使用不同频率和相位；

数据延迟及控制信号对齐；

长时间运行和计数器回绕。

12.3 算法模块

IQ、FIR、DDS 等算法模块应优先使用 MATLAB 或其他高精度模型生成输入向量和期望输出：

参考模型生成测试输入；

testbench 读取测试向量；

HDL 运行并输出结果；

自动比较实际值与期望值；

使用由定点格式推导出的误差阈值；

保存失败样本，便于复现。

12.4 测试结果

测试结束时必须给出明确结果，例如：

TEST PASSED

出现任何断言失败时测试应返回失败状态，不允许打印错误后仍以成功状态结束。

13. 模块完成标准

模块同时满足以下条件后才视为完成：

接口和参数已经明确；

模块头中文使用说明完整；

每个端口和参数都有中文注释；

RTL 可以通过语法检查和编译；

自检式 testbench 全部通过；

正常、边界和主要异常场景已覆盖；

参数合法性检查有效；

复位行为明确且已测试；

跨时钟域处理明确；

无意外锁存器、组合环路和派生时钟；

综合成功；

已检查综合警告；

已检查 CDC 报告；

已检查时序报告；

已记录资源使用和最高工作频率的初步结果；

测试可以独立重复执行。

仿真通过不等于硬件稳定。未完成综合、CDC 和时序检查的模块不得标记为最终完成。

15. Codex 执行要求

Codex 每次实现新模块前，先给出以下内容：

模块职责；

上下游连接；

参数表；

端口表；

时钟域和复位方式；

数据及定点格式；

握手时序；

预计延迟和吞吐率；

异常处理方式；

测试计划。

若用户明确要求先确认接口，则暂时不要编写 RTL。接口获得确认后，再完成：

RTL 文件；

对应 testbench；

必要的测试向量或参考模型；

仿真脚本；

验证结果说明。

新增代码中的注释统一使用中文。若修改已有英文注释，仅在本次修改涉及该段逻辑或需要澄清接口时将其改为中文，避免为翻译注释而制造无关的大规模变更。
