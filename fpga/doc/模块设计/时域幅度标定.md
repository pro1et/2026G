# 时域波形幅度标定方案

## 1. 文档状态

本文档记录当前已经确认的时域波形幅度标定方案以及后续可升级的掉电保存方案。

当前版本采用易失性标定：标定结果只保存在 PS 运行期内存中，设备不断电、不复位时持续有效；设备掉电或 PS 复位后标定结果丢失，并恢复使用程序内置默认值。

SD 卡掉电保存不属于当前版本实现，仅作为后续升级方案记录。

## 2. 标定目标

系统需要测量真实输入信号的峰峰值，输入峰峰值范围为：

```text
50 mVpp ～ 250 mVpp
```

标定参考信号采用实际输入端测得的：

```text
250 mVpp 正弦波
```

标定目标是消除固定模拟链路中的综合比例误差，使 PS 能够根据 PL 输出的峰峰值码数计算真实输入峰峰值。

## 3. 前提条件

本方案成立需要满足以下条件：

1. 前端放大倍数在标定完成后保持固定。
2. 标定和正常测量使用相同的模拟通道、放大电路、ADC 通道及采样配置。
3. 最大输入信号经过放大后不得使放大器或 ADC 输入发生削顶。
4. 模拟链路在 50 mVpp～250 mVpp 范围内保持线性。
5. 250 mVpp 标定信号必须是在系统实际输入端确认的真实峰峰值，不能只依赖信号发生器面板的标称值。
6. 标定时读取的必须是本次采集完成后的 PL 结果，不能使用上一帧残留数据。

前端放大倍数不需要由 PS 显式知道。只要放大倍数固定且模拟链路未削顶，放大器实际增益、AD 模块衰减比例、ADC 参考电压和固定电阻误差都会被统一包含在标定结果中。

## 4. PL 与 PS 职责划分

### 4.1 PL 端

PL 负责完成以下工作：

1. 采集完整 ADC 数据帧。
2. 对采集结果计算峰峰值。
3. 对多个周期或多组峰峰值结果进行平均，降低单周期采样误差及随机波动。
4. 将最终稳定的峰峰值码数写入 BRAM 的峰峰值结果字段。
5. 在结果写入完成后产生有效的采集完成状态。

PS 不再对原始波形重复执行峰峰值统计，也不再对 PL 的多周期结果进行二次平均。

### 4.2 PS 端

PS 负责完成以下工作：

1. 接收 HMI 的标定请求。
2. 启动一次新的 PL 测量。
3. 等待 PL 测量完成，并检查 ready、busy、done 和 error 状态。
4. 从 BRAM 读取 PL 计算完成的多周期平均峰峰值码数。
5. 将该结果保存到 PS 运行期变量 `cal_vpp_code`。
6. 在设备不断电、不复位期间持续使用该标定结果。
7. 后续测量时使用相同比例关系，将 PL 结果换算成真实输入电压。
8. 设备掉电或 PS 复位后恢复程序内置默认标定值。

当前版本不向 SD 卡、QSPI、EEPROM 或其他非易失存储器写入标定结果。

## 5. 标定参数定义

定义：

```text
CAL_REF_VPP_UV = 250000
```

其单位为微伏，对应真实输入的 250 mVpp。

定义：

```text
cal_vpp_code
```

表示输入 250 mVpp 正弦波时，PL 多周期平均后写入 BRAM 的峰峰值码数。

当前版本中，`cal_vpp_code` 是 PS 内存中的运行期变量。标定成功后覆盖默认值，掉电或复位后丢失。

定义：

```text
DEFAULT_CAL_VPP_CODE
```

表示程序编译时设置的默认峰峰值标定码数。具体数值应使用实验室实测的典型标定结果确定。当设备上电后尚未执行现场标定，或者设备掉电重启时，PS 使用该默认值。

定义：

```text
measured_vpp_code
```

表示正常测量时，PL 多周期平均后写入 BRAM 的峰峰值码数。

## 6. 换算公式

理论标定比例为：

\[
K=\frac{250000}{cal\_vpp\_code}
\]

其中 \(K\) 的单位为 `μV/code`。

后续实际输入峰峰值为：

\[
V_{pp}=
\frac{measured\_vpp\_code\times250000}
     {cal\_vpp\_code}
\quad \mu V
\]

PS 建议直接保存整数 `cal_vpp_code`，不保存浮点系数。换算时使用 64 位无符号整数，并在除法前加入舍入量：

```c
vpp_uv = ((u64)measured_vpp_code * 250000U
          + cal_vpp_code / 2U)
         / cal_vpp_code;
```

这样可以避免浮点库开销以及系数量化造成的额外误差。

## 7. 当前 HMI 标定流程

根据 `fpga/HMI/HMI逻辑.txt`，时域页面的幅度标定按钮触摸释放事件为：

```text
65 01 2C 00 FF FF FF
```

字段含义为：

```text
65       Nextion 触摸事件标识
01       时域页面 page 1
2C       标定按钮组件 ID
00       按钮释放事件
FF FF FF 事件结束符
```

当前标定交互流程如下：

```text
用户向实际输入端施加 250 mVpp 正弦波
                    ↓
HMI发送 65 01 2C 00 FF FF FF
                    ↓
PS 启动一次新的 PL 测量
                    ↓
PL 完成多周期峰峰值计算和平均
                    ↓
PS 等待 done 并检查 error
                    ↓
PS 从 BRAM 读取峰峰值结果
                    ↓
检查结果合法后写入运行期变量 cal_vpp_code
                    ↓
刷新时域波形和横坐标
                    ↓
加载峰峰值、有效值和基频值
```

标定完成后的时域波形默认显示一个周期。后续所有峰峰值、有效值以及频域电压幅值均根据当前 `cal_vpp_code` 进行换算。

在同一次上电运行期间再次按下标定按钮时，PS 重新执行完整标定流程。只有新标定结果通过合法性检查后，才允许覆盖原来的 `cal_vpp_code`；如果新标定失败，继续使用原来的运行期标定值。

标定值在设备不断电且 PS 不复位时一直保持。掉电或复位后标定值丢失，程序重新使用 `DEFAULT_CAL_VPP_CODE`。

当前 HMI 逻辑没有单独定义标定成功或失败的提示组件，PS 实现时不得擅自占用其他文本组件。后续如增加提示对象，再补充相应页面、组件 ID 和指令。

## 8. 标定结果合法性检查

PS 保存 `cal_vpp_code` 前至少检查：

1. PL 时钟已经锁定。
2. PL 当前允许启动测量。
3. 本次测量已经完成。
4. PL 未报告采集、FIFO、CDC 或 BRAM 错误。
5. BRAM 中的峰峰值结果不为 0。
6. 峰峰值结果处于 ADC 数据位宽允许的合法范围内。

如果任何检查失败，本次标定无效，PS 必须保留原有标定值，并禁止使用失败结果覆盖 `cal_vpp_code`。

当前 HMI 尚未定义独立的失败提示对象，因此当前版本不擅自发送失败提示；后续增加提示组件后再补充通知逻辑。

## 9. 正常测量流程

完成一次有效标定后，每次时域测量均采用以下流程：

1. PS 启动 PL 测量。
2. PL 完成多周期峰峰值计算并写入 BRAM。
3. PS 读取 `measured_vpp_code`。
4. PS 使用 `cal_vpp_code` 换算真实峰峰值。
5. PS 将换算后的电压发送给 HMI。

时域页面重新测量事件为：

```text
65 01 23 00 FF FF FF
```

该事件要求重新启动 PL 写 BRAM，随后 PS 重新读取 BRAM、绘制时域波形并加载峰峰值、有效值和基频值。测量结果继续使用上一次有效的 `cal_vpp_code`。

峰峰值、有效值和基频显示对象分别为：

```text
page1.t32  峰峰值，文本中包含数值和电压单位
page1.t33  有效值，文本中包含数值和电压单位
page1.t34  基频值，文本中包含数值和 Hz 单位
```

频域页面的基频、谐波 1 和谐波 2 电压幅值也使用当前标定关系进行换算。峰峰值、有效值和频谱幅值的数据格式不同，PS 必须分别按照对应 PL 结果格式完成换算，不能把峰峰值公式不加区分地直接用于均方值或未归一化 FFT 结果。

显示单位可根据结果大小选择：

```text
μV
mV
V
```

本项目当前输入范围为 50 mVpp～250 mVpp，HMI 默认使用 mVpp 显示即可。

## 10. 当前版本的掉电行为

当前版本明确采用易失性保存：

```text
上电
  ↓
加载 DEFAULT_CAL_VPP_CODE
  ↓
用户执行现场标定
  ↓
新 cal_vpp_code 保存在 PS 运行期内存
  ↓
不断电且不复位时持续有效
  ↓
掉电或复位
  ↓
运行期标定值丢失
  ↓
再次加载 DEFAULT_CAL_VPP_CODE
```

因此，当前方案不能保证现场标定值在断电后保留。程序默认值应使用实验室实测的典型结果，以保证设备断电重启后仍能提供基本可用的测量结果。

## 11. 后续升级：SD 卡掉电保存

后续可将 `cal_vpp_code` 保存到启动使用的 SD 卡，使设备断电重启后自动恢复现场标定值。该方案不属于当前版本，实施前需要在 Vitis standalone domain 中启用 `xilffs` 文件系统库。

### 11.1 双备份文件

建议在 SD 卡根目录使用两个标定文件：

```text
0:/CAL_A.BIN
0:/CAL_B.BIN
```

标定记录建议包含：

```c
typedef struct {
    u32 magic;          // 固定文件标识
    u32 version;        // 数据格式版本
    u32 sequence;       // 成功保存一次后加 1
    u32 channel;        // ADC 通道
    u32 reference_uv;   // 250000，单位为 μVpp
    u32 cal_vpp_code;   // PL 多周期平均峰峰值码数
    u32 reserved[2];    // 后续扩展
    u32 crc32;          // 记录内容校验
} CalibrationRecord;
```

### 11.2 上电加载

升级后的上电流程为：

1. 挂载 SD 卡。
2. 分别读取 `CAL_A.BIN` 和 `CAL_B.BIN`。
3. 检查 magic、version、数值范围和 CRC32。
4. 两份均有效时选择 sequence 较大的记录。
5. 仅一份有效时使用有效记录。
6. 两份均无效或 SD 卡不可用时回退到 `DEFAULT_CAL_VPP_CODE`。

### 11.3 安全写入

新标定结果不得直接覆盖当前唯一有效文件。应写入非活动文件，执行 `f_sync` 和 `f_close` 后重新读取并校验 CRC；确认新文件完整有效后，才把它作为最新记录。

双文件交替写入可以降低标定保存过程中突然掉电导致全部标定记录损坏的风险。保存失败时必须保留旧文件和当前运行期标定值。

### 11.4 升级后的优先级

升级后的标定值选择优先级为：

```text
本次上电后新完成的有效标定
            >
SD 卡中最新的有效标定记录
            >
程序内置 DEFAULT_CAL_VPP_CODE
```

在 SD 持久化功能正式实现并验证前，系统仍按第 10 节的易失性方案运行。

3. 有效值 PL 结果是均方值还是已经开方后的有效值，以及对应标定换算方式。
4. FFT 幅值的归一化方式及频域电压换算公式。
5. 标定成功和失败的 HMI 提示对象。
6. 是否以及何时启用 SD 卡持久化升级。
